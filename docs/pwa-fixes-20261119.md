## 一、六个问题的修复与验证

### EXP-01 订单 CSV 未跟随筛选、缺业务列 —— 已修复并验证

**根因**：PWA 的 `exportCSV()` 走的是通用同步导出（`mobile_entities` 原始行，列固定为 `kind,id,version,data`），既没有把页面日期范围传给后端，也没有业务列。而后端 `Nali_finance::export()` 本就实现了带日期过滤、BOM、公式注入防护和业务列的导出，只是 PWA 没用它。

**修复**：
- 新增 `Pwa::finance_export()`，复用 `Nali_finance::export()`；新增路由 `pwa/v1/export`；
- 前端改为直接下载 `/index.php/pwa/v1/export?view=&from=&to=&language=`，`from/to` 取**已应用**的页面范围。

**接口级验证**（真实登录、真实数据）：

| 请求 | 结果 |
| --- | --- |
| `from=2026-11-19&to=2026-11-19` | 数据 1 行，仅 `NALI-20261119-000002` |
| `from=2026-11-18&to=2026-11-18` | 数据 1 行，仅 `NALI-20261118-000001` |
| `from=2026-11-18&to=2026-11-19` | 数据 2 行 |
| `view=ledger` | 流水列（流水号/订单号/营业日/类型/方式/金额/操作人…）1 行 |
| 未登录访问 | 401 |
| 起止颠倒 | 422 `invalid_range` |

表头已变为业务列：`订单号,开单日期,客户,项目,技师,状态,金额 EUR,收款方式,操作人,备注`，带 BOM，`Content-Disposition: attachment; filename="nali-orders-2026-11-19.csv"`。

### ACC-01 当前店长被标为停用 —— 已修复并验证

**根因**：`COALESCE(...) AS revoked` 经 MySQL/PHP 返回的是**字符串** `"0"`，前端 `a.revoked ? 停用 : 启用` 把 `"0"` 判为真，所以启用账号显示停用。

**修复**：后端强制转 `int`（`id`/`revoked`/`version` 三个字段），前端改为 `Number(a.revoked)!==0` 比较。

**验证**：`auth/staff_list` 实际返回 `revoked=0 (int) version=0 (int)`，页面判定 `ACTIVE`。

### AUD-01 操作记录混用英文类型、时间差一小时、操作人显示数字 —— 已修复并验证换算

**根因（三条独立）**：
1. 投影把 `entity`（`order`/`cash_day`/`appointment`）塞进 `action` 字段，而标签表只认 `save_order`/`checkout` 这类操作名 → 回落成英文原文；
2. `merchant_audit.created_at` 存的是 **UTC**（DB 时区 SYSTEM=UTC，实测 `NOW()=utc_now`），页面原样输出；而同轮本地操作的 `occurred_at` 走 `wall()` 转成 Rome，于是同一批出现 09:09 与 10:09；
3. 操作人只拿到 `actor_id`。

**修复**：按 `entity + after.action` 映射业务文案；`created_at` 按 UTC 解析后转 Europe/Rome；新增 `actorLabel()` 依次从 `actor_name`、本地 `actor` 实体、当前登录身份解析姓名。

**验证**：`2026-11-19 09:09:12`（UTC）现渲染为 `2026-11-19 10:09:12`（Rome），与本地操作口径一致。

### SCH-01 排班时间显示 12 小时制 —— 已修复

**根因**：`<input type="time">` 的显示格式由浏览器区域设置决定，页面语言无法强制 24 小时制，所以 Chrome 显示 `09:00 AM`。

**修复**：新增 `timeField()`，改为 `HH:MM` 文本输入 + `pattern` 校验 + `title` 提示，并提供输入归一化（`9:00` → `09:00`）；已替换技师周排班、临时安排、冲突编辑三处共 6 个时间字段。

### SCH-02 请假／恢复周排班仍显示班次字段 —— 已修复

**修复**：新增 `syncShiftFields()`，按安排类型隐藏并**禁用**班次字段（隐藏字段同时 `disabled`，避免提交无效值）；技师临时安排与冲突编辑两处都已接入。

### FIN-01 起止日期颠倒提示不准确 —— 已修复

**修复**：拆成三条提示——未选完整日期、开始晚于结束、超过 366 天；校验不通过时不改动已应用范围，旧结果保留。
