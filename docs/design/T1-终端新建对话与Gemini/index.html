状态与边界（供你确认）

情况界面表现为什么这么定
终端 Tab 新建 选目录后弹 sheet 选「DSH / Gemini / Claude / 纯终端」，创建 tab 后自动启动对应后端并进入浮层 保留原有「先选目录」肌肉记忆，少点一步；想进空 shell 仍可选最后一项
Gemini 历史解析 GET /chat 根据 agent kind 分发：Claude 读 ~/.claude/projects/*.jsonl；Gemini 优先读 ~/.gemini/tmp/*/chats/session-*.json，找不到时返回 fallback: 'pane'，前端显示「终端摘要」提示条 Gemini CLI 各版本会话目录/命名可能变化，或新会话未落盘；有降级保底就不会出现对话页白屏或报错
启动返回 agent_not_ready 提示「Gemini 正在启动，若停在登录或信任提示可切到终端查看」，同时保留切终端入口 首次在新目录启动 Gemini CLI 可能弹 Trust Folder / OAuth 提示，herdr 判未就绪，切终端即可完成交互
点顶栏 ＋（运行中） 弹「新建对话」sheet：默认提供同目录新开 DSH / Gemini / Claude（建新 tab 切过去），底部红字项才是「结束当前对话」 防止在 Gemini / Claude 跑任务中途误删原会话；DSH 模式下「结束当前对话」等价于原 /dsh/close
宿主机未装 gemini 启动页显示错误卡片（带 stderr 原文）+「切到终端查看 / 重试」，不关闭浮层、不回退清空状态 此前实测本机默认 PATH 里未检测到 gemini 可执行文件，必须把前置缺失明确告诉用户（开发前也需在宿主机确认 PATH 中可用）
动态标题与气泡名 顶栏标题、气泡 .who、外层输入框占位均按后端动态展示 DSH / Gemini / Claude 修掉当前 ui.html 把非 DSH 的 agent 一律显示为「Claude」/「DSH」的硬编码
